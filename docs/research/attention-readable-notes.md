# 长视频总结 / 知识笔记的注意力与可读性准则

> 调研日期：2026-08-21  
> 适用范围：`bilibili-digest` Chrome 侧栏中的长视频总结、分层知识笔记、折叠/展开与 Markdown 导出。  
> 结论口径：**规范要求**可直接作为验收底线；**实验支持**只说明相近条件下的趋势；**产品默认值**是结合本项目 320px 起的窄侧栏作出的设计假设，必须通过真实内容与用户任务验证。

## 1. 先给结论：建议采用的设计准则

### 1.1 信息结构：先给地图，再给细节

1. 每份笔记固定按完整有序层级输出：
   - 一级：`一、主题`；
   - 二级：`1. 子主题`；
   - 三级：`1.1 知识点`。
2. 每个可折叠标题在收起时仍显示三项：**编号 + 能表达主题的短标题 + 一句结论**；不能只显示“详情”“更多”。W3C 要求标题和标签描述主题或目的，语义结构也应可由程序识别。[WCAG 2.4.6](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels)、[WCAG 1.3.1](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)
3. 每个三级知识点用相同顺序记录四个问题：
   1. **是什么**：一句定义或结论；
   2. **为什么**：解决的具体问题或带来的价值；
   3. **什么时候用**：触发条件、适用边界，必要时含“不适用”；
   4. **怎么用**：最短可执行步骤、示例或公式。
4. 视频时间点作为知识点的辅助入口，不要让逐句时间轴取代知识结构；一个知识点优先保留最能定位解释或演示的 1–3 个时间点。
5. 删除不增加理解的信息：寒暄、重复复述、空泛评价、无解释的术语堆、与知识点无关的口头过渡。W3C COGA 建议长内容提供摘要、保持简洁、使用清楚的词和易理解的页面结构；早期 Web 写作实验也发现简洁和可扫读版本在其测试任务中可用性更高，但该实验不能证明固定百分比会复现于本产品。[W3C COGA Design Guide](https://www.w3.org/TR/coga-usable/design_guide.html)、[Morkes & Nielsen 原始研究页面](https://www.nngroup.com/articles/concise-scannable-and-objective-how-to-write-for-the-web/)

**证据强度：中—强。** 语义标题属于 WCAG 可验收要求；“四问模板”和三层编号是针对本产品目标的内容设计，不是研究证明的唯一最佳结构。

### 1.2 折叠与渐进披露：减少首屏密度，但不能藏掉线索

1. 使用语义化 disclosure：优先原生 `<details><summary>`；若使用自定义按钮，至少同步 `aria-expanded`，并支持 `Enter` / `Space` 切换。[WAI-ARIA Disclosure Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)
2. 建议只有**两层交互折叠**：
   - 一级主题可展开二级目录；
   - 二级子主题可展开三级知识点；
   - 三级知识点内部的“是什么/为什么/何时/怎么”直接呈现，不再套第四层折叠。
3. 初始状态建议：整体概述始终可见；第一个一级主题展开，其余一级主题收起；二级默认收起。提供“全部展开 / 全部收起”，并记住当前笔记的展开状态。
4. 不允许同层只能展开一个。阅读对照、查找前后知识点时，用户应能同时保留多个主题。
5. 展开不触发再次调用模型；思维导图也应由已有层级数据在本地确定性转换，避免额外 token 消耗。
6. 展开按钮的可点击区域至少 `24 × 24 CSS px`，更适合作为本产品默认值的是整行至少 40–44px 高；键盘焦点必须始终可见。[WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[WCAG 2.4.7](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible)

**证据强度：混合。** Disclosure 的状态、语义和键盘行为有 W3C 指南支持，24px 是 WCAG 2.2 AA 底线；“两层交互折叠”“默认展开第一项”“40–44px 行高”是产品默认值。没有找到足以证明“所有知识笔记最多只能三层”或“某个默认展开数量普遍最优”的高质量证据。

### 1.3 字号、行高、行宽：建立清楚层级，允许用户放大

建议初始排版变量（待真实侧栏验证）：

| 角色 | 产品默认值 | 用途 |
| --- | ---: | --- |
| 页面 / 视频标题 | `20px / 1.35`，700 | 当前对象 |
| 一级主题 | `18px / 1.45`，700 | 主章节 |
| 二级子主题 | `16px / 1.5`，650–700 | 可折叠分组 |
| 正文 / 三级知识点 | `15px / 1.65`，400–500 | 连续阅读 |
| 辅助信息 / 时间点 | `12px / 1.5`，500 | 非核心元数据；不可承载关键结论 |

验收底线：

1. 不用只靠字号表达层级；同时使用语义标题、字重、间距和编号。颜色只作辅助。
2. 正文列宽限制在 `max-inline-size: 40em` 以内；对于中文等 CJK 文本，优先确保单行不超过约 40 个字形。WCAG 1.4.8 给出 80 字符、CJK 40 字形，但它是 AAA 且要求提供可达到这些效果的机制，并非强制作者默认采用该精确宽度。[WCAG 2.2，1.4.8](https://www.w3.org/TR/WCAG22/#visual-presentation)
3. 设计必须容纳用户覆盖为 `line-height: 1.5`、段后距 `2em`、字距 `0.12em`、词距 `0.16em` 时不裁切、不重叠；注意这项 WCAG 1.4.12 要求的是**兼容覆盖值**，并不要求默认就设置全部数值。[WCAG 1.4.12](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing)
4. 文本放大到 200% 时不可丢内容或功能；相当于 320 CSS px 宽时应单向重排，无需横向滚动阅读普通文本。[WCAG 1.4.4](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)、[WCAG 1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow)
5. 正文与背景对比度至少 4.5:1，大号文字至少 3:1；交互状态和折叠箭头等必要非文本信息至少 3:1。[WCAG 2.2，1.4.3 与 1.4.11](https://www.w3.org/TR/WCAG22/#contrast-minimum)

**证据强度：强（兼容性、重排、对比度），中（行宽），弱—中（具体默认字号）。** 一项 115 人、5.9 英寸手机的简体中文实验发现 10/12/14pt 与 1.25/1.5/2 倍行距会影响阅读时间、主观难度和疲劳，字体大小还影响准确率；但设备、pt 到 CSS px 的换算及侧栏情境不同，不能据此宣布某个 px 值为普适最优。[Zhu, Su & Dong, 2021](https://doi.org/10.1093/iwc/iwab020) 屏幕英文研究也显示阅读速度、理解、偏好之间并不总一致，55 字符只是特定实验中的折中而非通用定律。[Dyson & Haselgrove, 2001](https://doi.org/10.1006/ijhc.2001.0458)

### 1.4 扫读与注意力：让用户先捕捉结论

1. 折叠标题使用“结论型标题”，例如“`1. Flex 布局——用一维主轴控制排列`”，不写“CSS 知识点介绍”。
2. 一段只回答一个问题；知识点四问各自以粗体短标签开头。避免把定义、价值、适用条件和操作混成一个长段。
3. 每段先结论后解释；列表项尽量平行，同层使用同样语法。首屏只保留概述、主要目录和最重要操作。
4. 术语首次出现时使用“中文常用说法（英文 / 缩写）+ 一句解释”；后文才使用简称。不要用标签云重复已经在标题和正文出现的术语。
5. 重要性通过位置、标题和留白表达，避免每段都使用彩色卡片、粗体或徽章。COGA 明确建议熟悉且一致的层级、清楚页面结构、留白、分块和简洁文本。[W3C COGA Design Guide](https://www.w3.org/TR/coga-usable/design_guide.html)
6. 认知负荷理论支持“有限处理容量会被无关活动占用”这一一般机制，但 Sweller 1988 研究的是问题解决与图式习得，不是折叠面板实验。因此它只能支持减少无关内容的方向，不能直接证明某个卡片数量或层级深度。[Sweller, 1988](https://doi.org/10.1207/s15516709cog1202_4)

**证据强度：中。** 清楚标题、简洁、分块有规范与研究方向支持；具体文案长度和高亮数量需要在本产品中测试。

### 1.5 窄侧栏 / 移动阅读

1. 以 `320 CSS px` 宽作为最低重排验收视口：正文、折叠控件和工具栏不得造成整页横向滚动。
2. 顶部/底部 sticky 区域不得遮挡键盘焦点或大面积挤压正文；在 320px 宽、200% 文本缩放下重点测试。[WCAG Reflow 说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow)
3. 窄屏按钮可换行或分成“主要操作 + 更多”，不要缩成难点击的图标。下载字幕、下载总结、思维导图三个动作应有可见文本或明确 accessible name。
4. 时间点、折叠箭头与标题保持同一阅读行的逻辑顺序；标题过长时允许换行，不使用 `line-clamp` 隐藏知识标题。
5. 展开后避免程序化把焦点移到正文；保留在触发按钮上，状态由 `aria-expanded` 表达。只有用户明确执行“跳到时间点”等导航操作时才移动视图。

## 2. 建议界面骨架

```text
视频标题
一句整体结论（始终可见）

[下载字幕.md] [下载总结.md] [思维导图] [全部展开]

▼ 一、页面结构 —— 先拆模块，再按视觉顺序实现
    ▶ 1. 顶部区域 —— 广告与导航是两个独立层
    ▶ 2. 商品区域 —— 重复卡片应抽成统一结构
▶ 二、CSS 布局 —— 定位与弹性布局解决不同问题
▶ 三、响应式 —— 小屏不是等比缩小，而是重排
```

展开二级项后：

```text
▼ 1. 顶部区域 —— 广告与导航是两个独立层
    1.1 顶部广告的绝对定位
    是什么：……
    为什么：……
    什么时候用：……
    怎么用：……
    [01:40] [01:53]
```

该骨架刻意把“目录线索”留在收起态，避免渐进披露退化为“用户不知道里面有什么”。

## 3. 可直接执行的验收清单

### 3.1 内容质量

- [ ] 全文编号连续且唯一，严格满足 `一、` → `1.` → `1.1`。
- [ ] 每个三级知识点都包含“是什么 / 为什么 / 什么时候用 / 怎么用”；缺少视频证据时明确写“视频未说明”，不让模型补造。
- [ ] 收起态标题本身能说明主题，并带一句结论；不存在仅叫“详情”“模块一”的标题。
- [ ] 术语首次出现有白话解释；无寒暄、重复时间轴、空洞评价和无解释标签堆。
- [ ] 时间点可追溯至字幕，且只是知识点入口，不把每句话都生成一张卡。

### 3.2 交互与无障碍

- [ ] 键盘仅用 `Tab`、`Shift+Tab`、`Enter`、`Space` 可操作所有折叠与下载按钮。
- [ ] 每个 disclosure 的可访问名称包含其编号和主题，`aria-expanded` 与视觉状态一致。
- [ ] 可同时展开多个同层主题；“全部展开 / 全部收起”行为可预测。
- [ ] 所有非行内点击目标达到 24 × 24 CSS px 或满足 WCAG 间距例外；焦点样式可见。
- [ ] 展开、下载、切换思维导图均不再次调用模型；只读取当前结构化结果。

### 3.3 排版与响应式

- [ ] 320 CSS px 宽无普通文本横向滚动；200% 文本放大无裁切、遮挡或功能丢失。
- [ ] 用户覆盖 WCAG 1.4.12 的文本间距后，标题、按钮和卡片不裁切、不重叠。
- [ ] 正文与背景至少 4.5:1，必要的 UI 边界和状态至少 3:1。
- [ ] 标题字号 / 字重 / 间距随层级递减，正文不小于本轮确认的产品默认值。
- [ ] 长标题自然换行；不以省略号隐藏关键知识点名称。

### 3.4 建议的验证任务（采纳准则后执行）

至少用 3 类真实视频笔记验证：技术教程、概念讲解、步骤演示。每类让用户完成：

1. 10 秒内指出视频的 3 个主要主题；
2. 找到一个具体知识点的“什么时候用”；
3. 在不同一级主题之间对照两个知识点；
4. 从折叠标题跳到对应视频时间；
5. 在 320px 宽和 200% 放大下完成下载总结。

记录任务完成率、首次定位时间、误展开次数、是否需要全文搜索，以及用户是否能复述一级结构。它们比“看起来更清爽”更能判断设计是否真正降低阅读难度。

## 4. 不应过度推断的结论

1. **不能说“人类只能处理 7±2 项”，所以目录必须少于 7 项。** 该经典结论不是这类侧栏导航的直接上限证据。
2. **不能说“三层是科学证明的最佳深度”。** 三层来自用户要求和当前内容模型；这里只建议把交互折叠限制为两层，以降低操作嵌套。
3. **不能把 WCAG 文本间距值当作默认视觉处方。** 1.4.12 的要求是用户覆盖这些值时内容仍可用。
4. **不能把 55 个英文字符或 40 个 CJK 字形称为所有屏幕上的唯一最佳行宽。** 前者是特定实验结果，后者是 WCAG AAA 的可配置目标。
5. **不能声称折叠一定减少认知负荷或提高理解。** 折叠减少同时可见内容，却增加点击与寻找成本；必须保留有信息量的标题，并用真实查找任务验证。
6. **不能只靠 AI 自评判断笔记“抓人”。** 应用真实视频、固定问题和可观察指标做对比测试。

## 6. 待用户确认的产品决策

在进入界面修改前，建议先确认是否采纳以下默认方案：

1. 固定三层内容编号，但只做两层交互折叠；三级四问直接可见；
2. 初始展开第一个一级主题，其余收起，并提供全部展开 / 收起；
3. 正文从 `15px / 1.65` 起步，一级 / 二级标题为 18px / 16px；
4. 收起态同时显示“标题 + 一句结论”，而不是只显示标题；
5. 思维导图从既有结构本地转换，不新增模型调用；
6. 用第 3.4 节任务验证后再调整字号、密度和默认展开策略。
